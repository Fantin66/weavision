> 版本：v6.2 | 更新：2026-08-28 | 品牌：织见（Weavision）| 本次修订：同步最新 demo 的“内容形变展开”、子树可见性、排版避让、字体与 AI 编排能力

## 一、定位（30 秒版）

**织见是一个“思维关系板”：用连接织出全局，用聚焦钻透局部。**

它不是画图工具，不是文件管理器，甚至不是思维导图。

思维导图把信息组织成一棵**树**——一级到五级逐层细化，层级和标题就是全部。但真实的信息结构是一张**网**：材料之间有关联，一级标题和三级标题可以直接串联，一个变化会顺着因果链传导到另一个节点。树形的组织方式，表达不了网的复杂度。

织见的全部设计，都围绕两个主旨展开：

| 主旨 | 一个字 | 解决的问题 | 回答 |
|------|-------|-----------|------|
| **连接** | 宽 | 元素之间的关联、逻辑框架与传导链如何呈现 | 织网 |
| **聚焦** | 深 | 如何把某一个节点彻底看透 | 钻探 |

宽度和深度，是产品存在的全部理由。**每一个功能的存在，都必须能回答"它为连接或聚焦做了什么"——回答不了的功能，就不该存在。**

### 1.1 面向谁，完成什么任务

首要用户是需要把材料、判断与结论连成推理链的知识工作者：投研、战略、产品规划、复杂项目负责人。一次有效使用应在 10 分钟内完成“放入一份证据 → 写下一个判断 → 连到一个结论 → 聚焦复核关系”的闭环。

第一阶段的验收不是功能数量，而是三件事：关系不会因删除、撤销或导入而丢失；用户能一眼分辨层级、证据、因果与反证；离开聚焦后能回到原来的空间与视角。

## 二、第一性原理：树与网

### 2.1 现有工具的局限

思维导图是"菜单逻辑"：一级标题挂二级，二级挂三级，逐级展开。它隐含两个假设：

1. **信息只按层级组织**——一个节点只能属于一个父节点，跨层级的关联无处安放；
2. **理解了结构就理解了内容**——看到标题树，就算看完了。

这两个假设都不成立。实际思考中：

- **材料之间存在关联**：一份研报、一段访谈、一组数据，天然互相印证，它们不属于任何一级标题；
- **层级可以跨越**：一级标题和三级标题之间的因果，往往比同级的罗列更重要；
- **层级之外还有元素**：支撑性文件（附件）和零散想法（便签）根本不在层级里，但它们同样是思考的一部分；
- **逻辑是传导的**：一个因子沿链路影响下一个，传导链不是目录结构能表达的。

### 2.2 真实的信息结构：一切元素皆在网中

```
     ┌── 附件A（支撑材料）──────┐
     │                            │
一级 ──┤── 二级 ──┼── 三级（跨两级连接）
     │              │
     └── 便签（想法）──┴── 附件B（跨类型连接）
```

织见的画布上有三类内容元素，**全部平等地作为网的节点**：

| 类型 | 是什么 | 在网中的角色 |
|------|--------|-------------|
| 导图节点 | 层级结构的主体 | 主干节点（树） |
| 便签 | 零散想法、发散性内容 | 层级外的节点（网） |
| 材料卡片 | 支撑性文件、网页链接 | 层级外的节点（网） |

再加上画笔涂鸦与自定义连线，元素之间可以任意互连——**同级可以连、跨级可以连、跨类型可以连**。层级只是网的一种结构，不是边界。

### 2.3 第一性原理

> **信息的组织方式是一张网，而不是一棵树。**
> **网的密度来自"一切皆可连"——层级内、层级外、跨类型、跨画布。**
> **理解一张网，需要两种视角的交替：鸟瞰全局（宽度），钻探局部（深度）。**
> **网织得越密，越需要聚焦——这正是聚焦功能存在的理由。**

由此得出产品设计的**第一原则**：每一项功能，要么让网织得更密、更可读（连接），要么让某个点被看得更清、更透（聚焦），要么支撑以上两者运转（工程）。三者缺一，功能就失去了存在的意义。

## 三、产品主旨：连接与聚焦

### 3.1 主旨一：连接（宽度）

**定义：展现元素之间的关联、逻辑框架与传导链。**

连接是分层递进的，从"树"到"网"到"跨界"：

| 形态 | 说明 | 例子 | 对应功能 |
|------|------|------|---------|
| 层级连接（树） | 父子/同级，继承与从属 | 主题→子主题→三级 | 导图节点系统 |
| 自由连接（网） | 任意元素跨层级、跨类型互联 | 一级↔三级、便签↔节点、附件↔节点 | C 键连接 |
| 关联挂接 | 便签/材料挂到节点当支撑 | 研报挂到"行业研究" | 拖拽关联 |
| 跨画布连接 | 同一概念在不同画布间的同一性 | 画布A的节点 ↔ 画布B的衍生节点 | 跃迁 |

设计原则：

1. **一切内容皆可连**：节点、便签、材料卡片可作为关系端点；画笔和自定义连线是视觉标注，不冒充可计算的图关系；
2. **连接要有语义**：每条关系必须有类型（关联 / 支撑 / 导致 / 反证 / 证据），必要时有方向和批注；
3. **连接即全局**：画布上呈现的不是目录，而是整个项目的关系全貌——这就是"宽度"。

### 3.2 主旨二：聚焦（深度）

**定义：看清某一个节点的直接关系网络及其可展开内容。**

网织得越密，单看一个点就越难——周围全是线和元素。聚焦就是给画布装一个放大镜：**只保留与当前节点有关的一切，其余退后，不删除。**

| 聚焦层 | 内容 | 视觉 |
|--------|------|------|
| 焦点 | 被聚焦的节点 | 放大、高亮、居中 |
| 一级关联 | 与焦点直接相连的一切：父/子、语义关系两端、关联的便签与附件 | 清晰 |
| 同级与非关联元素 | 不因“并列”而自动纳入关系 | 不显示，不干扰钻探 |
| 其他层级 | 当前版本不自动向二跳扩散 | 保持画布数据不变，退出即回到全局 |

设计原则：

1. **聚焦不删信息**：降格不是隐藏，背景保留语境，退出即复原；
2. **一进一出**：F 进入、F 退出，零成本切换视角；
3. **聚焦有深度**：焦点自带展开内容、批注（一句话评价）、跃迁（可追到别的画布）——一个点能被看透，也能被追到底。

### 3.3 两者的协同：一个使用闭环

```
织网 ──→ 鸟瞰 ──→ 钻探 ──→ 理顺 ──→ 跨界 ──→ 回到全局
```

1. **织网**：随手添加节点、便签、附件，拖出层级、自由连接、关联挂接——一切皆可连；
2. **鸟瞰**：退后一步看整张网，找传导链、找断裂处——这是宽度；
3. **钻探**：选中一个节点，F 聚焦，看它的直接关系网络，E 编辑展开内容，把它彻底想透——这是深度；
4. **理顺**：给关键连接加批注，写清"为什么连、怎么看"——网从此可读；
5. **跨界**：同一概念在别的画布有延伸时，J 跃迁过去继续——网跨画布延伸；
6. **回到全局**：F 退出，带着局部结论回到全貌，继续下一轮。

思考的本质就是宽与深的交替。织见把这个循环做成了快捷键。

## 四、功能全景：每一个功能的存在理由

完整盘点 demo 的全部功能，按"为连接 / 为聚焦 / 为支撑"归类。**这是本手册的核心章节——它回答了"为什么做了这么多功能"。**

### 4.1 织网侧：服务于"连接"的功能

| 功能 | 为连接做了什么 | 状态 |
|------|---------------|------|
| **导图节点系统** | 提供网的"主干"：层级结构（Tab/Enter/Alt/蓝点拖线/右键改父级），4 级视觉降级让层级一眼可辨 | ✅ |
| **便签** | 层级外的发散节点：零散想法随时落画布，7 色区分 | ✅ |

## 五、核心机制详解

### 5.1 连接的四重奏

**第一重：层级连接（树）**——织见保留了思维导图的全部能力（Tab 子节点/Enter 同级/Alt 排序/提降级/折叠），因为树是网的基础骨架。4 级视觉降级（根实心、一级白底彩边、二级灰底彩条、三级透明）让层级关系一眼可辨。

**第二重：自由连接（网）**——这是超越思维导图的第一跳。选中两个任意元素按 C 键，跨层级、跨类型建立连接，绿色虚线贝塞尔+端点圆点；也可以从节点右侧蓝点拖出，拖到节点=改父级、拖到便签/卡片=自由连接。

**第三重：关联挂接（attach）**——这是材料入网的方式。把便签或材料卡片拖到导图节点上，即成为该节点的支撑材料（节点右上角橙色角标计数，hover 时关联物整体高亮）。与自由连接的区别：attach 有主从（材料服务于节点），自由连接是对等。

**第四重：跨画布连接（跃迁）**——项目含多个画布，同一概念在画布间延续。选中元素按 J 选择“目标画布 + 目标元素”，之后按 J 直接定位到该元素；元素左下角 ↗ 标记提示有跃迁。**网从单画布延伸到项目级。**

### 5.2 批注：连接的语义层

思维导图的线是哑的——它只表示“有关系”，不表示“什么关系、什么看法”。织见里，**语义关系、自定义连线、画笔以及任何元素，都可以按 A 添加一句话批注**，常驻画布：

- 连接线批注写在中点：备注"为什么连""证据在这"；
- 元素批注写在下方：对该事物的一句话评价；
- 画笔批注写在中点：圈画时的即时标注。

**连接负责画出"有什么关联"，批注负责说清"是什么关联、怎么看"**——批注理顺了连接的思路与方向，让传导链从"一条线"变成"一段有理由的推理"。

### 5.3 聚焦：分层钻探

按 F 进入聚焦后，画布按"与焦点的直接关系"收束：

```
非关联内容退出视图 → 一级关联（高亮边框）→ 焦点（放大+发光）
```

一级关联的计算（getRelated）非常关键，它决定"关系网络"的边界：**子节点、父节点、语义关系两端、关联的便签/材料、挂接了自己的节点**。同级节点不会仅因并列而显示，二级关联当前也不自动扩散——先确保一次钻探足够清晰。进入聚焦时 camera 平滑居中，焦点若有展开内容则自动展开。退出时恢复全部折叠状态与视角，**零痕迹**。

### 5.4 展开内容：元素的形变阅读区

**这是与思维导图的根本区别。** 思维导图里节点只是一个标题概括，内容要靠分支、旁注、外部文档承载——元素自己是不说话的。织见里，**内容元素（导图节点、便签、材料卡片）本身可以承载展开内容**：

- 每个内容元素自带一份 Markdown `detail`；常态只保留简标题，右缘使用“文档”把手提示可阅读内容；
- 点击把手时，元素**自身向下形变**：标题区保持原位，阅读区在元素内部生长；它不是下方外挂卡片；
- 阅读区的宽度先按文本长度取得舒适值，再进行换行和高度计算；超长内容以换行与最大阅读高度约束；
- 展开期间，系统以临时布局推开会相撞的节点、便签和材料卡片；收起时高度、宽度和邻居位置平滑回弹到展开前坐标；该临时形变不写入用户的画布排布与撤销历史；
- 展开把手是“文档 / 上箭头”，专用于内容阅读；子树控制保留“− / +隐藏数量”，专用于结构折叠，二者不能混用；
- 聚焦到含 `detail` 的内容元素时自动展开。连线和画笔以批注承载说明，不作为当前版本的展开内容载体。

由此产生明确的职责划分：

| 载体 | 职责 | 示例 |
|------|------|------|
| **展开内容（detail）** | 服务元素本身：定义、论证、结论 | 节点"行业研究"：为什么研究、结论、依据 |
| **便签（note）** | 发散性内容：想法、问题、待办 | "要不要考虑海外对标？""数据待核实" |

**错误用法**：在节点旁边贴便签做定义说明——那是把元素自身的内容职责外包给了便签。定义属于元素本身，写进展开内容；便签只承载发散。

### 5.5 跃迁：跨画布的同一元素

一个项目往往有多个画布，画布之间表达的内容不同，但概念是连续的：画布 A 的初始节点"行业研究"，可能是画布 B 中某个衍生节点的源头。这两个节点本质是同一个元素。

跃迁就是为这个同一性服务的：选中元素按 J → 选择目标画布与目标元素 → 元素带上 ↗ 标记；此后按 J 即直接跃迁并选中目标。它先解决“能准确跳到哪里”；双向链接与命名联动属于后续能力。

## 六、信息架构与数据模型

```
项目（Project）——每个项目一个画布集 + 一个材料库
├── 材料资源库：folders（嵌套文件夹）+ files（文件/链接，blob 存 IndexedDB）
├── 画布 1（Canvas）
│   ├── items：元素（mindNode 节点 / note 便签 / fileCard 材料卡片 / stroke 画笔 / connector 连线）
│   ├── links：语义关系（类型、方向、批注）
│   ├── previews：画布内预览窗口
│   └── camera：视角
├── 画布 2（同构）
└── ...
```

```
project:  { id, name, files[], folders[], canvases[] }
file:     { id, name, kind(img/pdf/doc/sheet/slide/text/link/media/other), size, mime, url?, created, folderId, thumb?, tw, th }
folder:   { id, name, parentId }
canvas:   { id, name, items[], camera{x,y,zoom}, previews[], links[] }
item:     {
            id, type, x, y, w, h,
            text, color,
            detail,            // 展开内容（Markdown；数据字段为兼容性保留 detail）
            annotation,        // 批注（一句话）
            parentId, children[],  // 层级连接（树）
            attachIds[],       // 关联挂接（材料/想法 ↔ 节点）
            jumpTo,            // { canvasId, itemId }，跃迁目标元素
            collapsed,         // 折叠状态
            birth,             // 出生时间（弹入动画）
            points[],          // stroke：轨迹点
            a, b,              // connector：端点（可绑定元素锚点或自由点）
            fileId, kind, thumb, tw, th   // fileCard：绑定材料
          }
link:     { id, aId, bId, relationType, directional, annotation }
```

`relationType` 只取 `related / supports / causes / contradicts / evidence`。`aId` 与 `bId` 必须指向仍存在的内容元素；删除、导入和撤销后统一清理悬空引用。画笔与自定义连线不写入 `links`，仅承担视觉圈画和注释。

产品支柱：**元素（内容）、连接（结构）、展开内容与批注（语义）、跃迁（跨画布同一性）**。元素是载体，连接是骨架，语义是血肉，跃迁是经络——齐备之后，一张网才既有全局又有深度，还能跨画布延伸。

### 6.1 AI 编排接口与画布生成规范

织见为同页面的 AI 调用预留了本地命令接口 `window.ZhijianAI`。它的目标不是替用户“画一张漂亮图”，而是让 AI 在**同一份可编辑数据模型**上执行人能够执行的操作：读取快照、创建/更新/删除元素、建立关系、挂接材料、改父子关系、设定布局、聚焦与撤销。

| 接口 | 用途 |
|------|------|
| `snapshot()` | 读取当前项目、画布、元素、关系和偏好设置的结构化快照 |
| `execute(command)` | 执行单条受校验命令，例如 `create_node`、`update_item`、`relate`、`attach`、`set_layout`、`focus` |
| `buildCanvas(plan)` | 用结构化计划一次生成或替换画布：节点、便签、材料卡、关系及布局 |
| `zhijian:command` 事件 | 供同页自动化通过事件提交命令，并可回收执行结果 |

AI 从文件生成画布时，应遵循以下映射：

1. **父子节点**：采用“主题 → 分论点 → 证据/行动”的稳定从属关系；只有确属层级时才建树；
2. **展开内容**：放入定义、背景、推理、摘要、限制与结论等“说明该元素本身”的 Markdown；
3. **便签**：放入开放问题、待验证假设、分歧、下一步行动等发散或临时内容；
4. **附件**：保留用户提供文件或链接的来源身份，以材料卡片挂接到其支撑的节点；不能把来源正文伪造为节点；
5. **语义关系**：用于跨层级、因果、支撑、反证与证据关系，必须选择 `related / supports / causes / contradicts / evidence` 之一；
6. **可追溯性**：保留来源名、原文片段或页码线索于材料/展开内容；不确定的关系应标注为待验证，而不是伪装为事实。

配套操作规范位于 [zhijian-canvas-orchestration SKILL](</D:/CodexData/.codex/skills/zhijian-canvas-orchestration/SKILL.md>)，其中包含输入提取、画布计划、命令安全与验收方法。

## 九、理念差距与路线图

### 9.1 差距分析（对照主旨）

**连接侧——基础语义已就位，链路阅读仍待深化：**

1. 关系类型、方向与批注已成为数据，下一步需提供“只看因果 / 只看证据 / 只看反证”的筛选；
2. 无传导链视图：仍无法沿 A→B→C 连续浏览和比较不同链路；
3. 画笔和自定义连线仍是视觉标注，不能参与图计算；这是有意边界，不能与语义关系混用。

**聚焦侧——能聚焦了，但不够直觉：**

4. 升格/降格是核心交互理念，目前主要依赖 F 键，未做成点击直觉化；
5. 当前只显示直接关系，后续可提供“关系深度 1 / 2 / 3”的显式控制，而不是默认扩散；
6. 聚焦没有关系类型过滤，复杂网络仍可能出现噪音。

**深化侧——机制已就位，体验粗糙：**

7. 展开内容的 Markdown 渲染仍较轻量，缺表格/图片/链接；
8. 跃迁可准确定位目标元素，但仍是单向；命名同步、反向标记和多重来源未支持；
9. 批注仅支持单条，一条关系如需多条备注需另开便签；
10. 本地材料内容不随 .board.json 导出，跨设备使用需要项目包。

### 9.2 路线图

**P0（可靠性优先，已实现）**

1. 关系类型、方向与批注写入数据模型；
2. 删除递归清理子树、关系、挂接与锚点；
3. 撤销/重做覆盖关系与视角；导入恢复关系、预览和材料索引；
4. 聚焦不改变元素坐标，退出恢复原视角；
5. 跃迁定位到具体目标元素。

**P1（交互直觉）**

4. 传导链视图：高亮所有进出链路，并可沿线浏览；
5. 升格/降格交互直觉化（点击节点即聚焦升格，其余降格）；
6. 聚焦关系过滤与层级深度控制；
7. 展开内容 Markdown 升级（表格/图片/链接）。

**P2（远期）**

8. 跃迁双向化：同一概念跨画布联动（命名同步、双向跳转标记）；
9. 画布间复制/移动元素；
10. 协作/分享；
11. 模板系统（投研框架/行业分析等预设）；
12. 导入/导出 .board 项目包（含文件 blob）。

## 附录：已知问题（技术侧）

1. 自动排版不够好：复杂树结构仍可能遮挡，需改进 subtreeH 计算和 GAP 参数；
2. 手动模式拖动后避让不智能：avoidOverlap 只是简单推开，可能推到不合理位置；
3. 排版逻辑需明确"新增自动排 + 拖动局部避让 + 手动重排按钮"三层逻辑；
4. .board.json 目前只带材料索引，不带 IndexedDB 中的文件 blob；
5. 搜索已限定当前画布；
6. PPT 预览为降级方案（提示下载）；
7. 链接预览需要保持 URL 校验与 iframe 隔离策略；
8. 大画布仍需空间索引和按视口绘制，避免内容增多后拖动卡顿。
