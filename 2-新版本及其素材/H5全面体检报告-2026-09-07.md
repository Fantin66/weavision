## 一、P0 —— 打包即崩 / 数据损坏（3 项，必须先修）

### P0-1 ★ 打包版启动即崩（任务栏图标路径）
- 位置：desktop/electron/main.js:24,74,110 + package.json `build.files`
- 机理：`applyTaskbarIcon` 用 `__dirname/icons` 找图标，但打包后 `__dirname` 在 app.asar 里，而 `files` 白名单（main.js/preload.js/icon.png）不含 icons/（已用 `asar list` 在 G9 安装包上实证）；`extraResources` 的 icons 落在 resourcesPath，代码不读那里。找不到图标 → 空图像 → 兜底 `win.setIcon(字符串路径)`，Electron 28 源码证实该路径加载失败会**同步抛异常** → 主进程未捕获 → 弹"A JavaScript error occurred in the main process"，应用无法启动。且抛出点在 close/theme 监听注册之前，退出确认与主题同步也不会注册。
- 修法：applyTaskbarIcon 增加 `app.isPackaged` 分支（参照 set-fantin-icon 用 process.resourcesPath），同时 `files` 加 `icons/**`，并把 `win.setIcon(string)` 兜底改成 `nativeImage.createFromPath` 后判空跳过。

### P0-2 ★ 导入 .fantin / 文件夹时小附件损坏
- 位置：main.js:285（readPackageFromDir）→ 渲染层 app.js:1167 new Blob
- 机理：`fs.readFileSync` 返回的 Buffer 挂在 64KB 共享内存池上，`buf.buffer` 把整块 64KB 都送进 IPC（实证：11 字节文件 → byteLength=65536）。渲染层直接 `new Blob([att.buffer])` 存进 IndexedDB → 小附件变成"正确字节+堆垃圾"的 64KB 文件，预览/再导出均损坏。import-fantin、import-folder、双击 .fantin 打开全中招。导出方向无此问题。
- 修法：main.js 改为 `buf.buffer.slice(buf.byteOffset, buf.byteOffset+buf.byteLength)`（或 `Uint8Array.from(buf)`）。

### P0-3 ★ 预览窗口创建必崩（it 未定义）
- 位置：preview.js:162（syncPvDom 的 pv 窗口创建分支）
- 机理：`el.dataset.pvZoom=String(it._morphPvZoom||1)` —— `it` 在该作用域不存在（从 ensureMorphDom 复制而来），10 个文件均为 "use strict" 且无 id="it" 元素。首次创建预览窗口即 ReferenceError：预览窗永远出不来，且 syncPvDom 每帧被 render 调用 → 每帧抛错；预览随 saveState 持久化 → 带预览的存档加载即卡死。
- 修法：删掉该行（下一行 applyZoom 会用局部 pvZoom=1 正确初始化），或改为 `String(pv._morphPvZoom||1)`。

## 二、P1 —— 重要功能失效（9 项）

### P1-1 ★ 打包配置过期：装出来是 H4 不是 H5
- package.json:21,28 extraResources 仍指 `织见-思维关系板-H4.html`、输出 `发行版/H4`；description 仍写 "(G10)"。main.js 开发分支已加载 H5。→ 打包前改为 H5 + 输出目录改名。

### P1-2 ★ g10/ 品牌图标目录未打包 → 装好后 logo 全裂
- app.js:320-334 LOGO_PRESETS 与闪屏 logo 引用 `g10/assets/logos/*.png`（g10、g12 是仅有的两个被引用的版本目录）。extraResources 只有 g12 → 打包版闪屏/顶栏/侧栏/设置里所有品牌图 404。→ extraResources 加 `{"from":"../../g10","to":"g10"}`（可只带 assets/logos 子集）。

### P1-3 ★ 网页预览手机模式缩放公式反向 + 画布缩放未生效
- render.js:353（syncPvContentZoom）与 :433（syncMorphDom 内联副本，两份已漂移）。手机分支 `ratio=(375/availW)*userZoom` 而 iframe 宽固定 375px：要装进 availW 宽的舞台应 `ratio=availW/375`（代码用了倒数）；且签名里的画布 zoom `z` 全程未使用——头注释承诺的"与画布缩放联动"不成立。
- 修法：改为 `ratio=(availW*z/375)*userZoom`，并把两份拷贝合并成一个辅助函数。

### P1-4 设置→数据→自动保存间隔按钮点击报错
- app.js:1714 调 `setupAutoSave()`，但该函数定义在 init() 内部（app.js:1506），全局不可见 → ReferenceError：按钮点了没反应、无 toast，新间隔要重启才生效（值本身已存）。→ 把 setupAutoSave 提为全局函数。

### P1-5 顶栏主题按钮在"跟随系统"（默认开）时失效
- app.js:677-684 themeBtn 只翻转 state.dark 后调 applyTheme()；autoTheme=true 时 applyTheme 会用系统主题覆盖回来（网页立即打回，桌面闪一帧后打回），toast 却显示已切换。设置里的明/暗按钮用了 _themeToken 所以正常。→ themeBtn 先关 autoTheme 或同样走 _themeToken。

### P1-6 展开内容编辑时，悬浮格式栏字体/字号/加粗/下划线全部无效
- editors.js:47 详情编辑也调 showNoteEditorChrome 显示完整 noteFormatBar，但按钮全部走 changeNoteFormat()（layout.js:847-863），其入口 `if(editingNoteId===null)return` 与详情编辑（只设 editingDetailId）不匹配 → 点击无任何反应（仅 MD 插入按钮有效）。→ changeNoteFormat 兼容 editingDetailId 目标。

### P1-7 蓝点悬停提示永久失效（状态变量分裂）
- interaction.js:57 写 `state.linkPointHover`、:54 读同字段，但渲染层 render.js:279 读的是裸全局 `linkPointHover`（state.js:103），后者从未被赋真值 → 拖出建子节点的悬停提示永远不画；且 state.linkPointHover 离开时不清理（陈旧 id）。→ 统一到一个变量并补清理。

### P1-8 选中栏"关联语义"按钮静默无效
- layout.js:779 传整个选中合成对象给 setLinkRelation(linkId)（editors.js:838 按 id find，对象永不匹配 → 直接 return）。右键菜单路径（layout.js:947）传 id 是对的。→ 统一传 item.id。

### P1-9 导入 .board.json 无确认、无撤销地覆盖当前画布
- interaction.js:932-969 直接替换 items/links/previews/camera 且不 pushHistory（对比 importOPML/importMarkdown 都有）；调用点 app.js:702 也不弹确认 → 误导入原内容不可恢复（localStorage 随后也被覆盖）。→ 加确认弹窗 + pushHistory。

## 三、P2 —— 数据安全隐患（8 项）

1. **"导出全部数据"名不副实**：app.js:1708-1713 提示"包含所有项目、画布、附件的完整备份"，实际 exportUserData 只导元数据（附件在 IndexedDB 里不导出），且全代码库无任何读取 `type:"userData"` 的导入路径 → 用户当备份用会丢全部附件且无法恢复。
2. **loadState 解析失败 → 静默用示例数据覆盖**：app.js:96 `catch{return false}` + init 视为首启 → ensureTutorProject + saveStateDebounced 在 1.5s 内覆盖损坏的 board-state，无隔离备份 → 一次坏解析变永久丢失。应先把坏数据改名留档。
3. **.fantin 导出→导入丢网页链接文件**：doExport fileMeta 只存 {oldId,name,mime} 无 url/kind；链接文件 getBlob 返回 null 被过滤（app.js:1142），导入 `if(!att)continue` 丢条目（app.js:1166）→ 画布上的链接卡变孤儿（丢名字/预览/打不开）。
4. **教程项目改动即被重置**：tutorial.js:27 版本门要求 canvases 恰好 7 个；用户在知见学堂里增删过画布 → 下次启动整个项目静默重建。另 tutorial.js:24 每次启动按名字删除"知见学堂/织见学堂/回归测试"项目——撞名的用户项目会被销毁。
5. **AI build_canvas 失败留半成品**：ai.js:112-185 pushHistory 与 `state.items=[]` 清空在各项校验（保留字/环/关联引用/附件）之前，aiExecute 捕获后不恢复状态（aiRunBatch 有快照恢复）→ 外部 AI 报错但用户看到被清空/半建的画布。
6. **AI set_layout/set_style/set_preferences 不可撤销**：ai.js:235-244 无 pushHistory，而导出的 AI Skill 文档承诺"每条命令自动 pushHistory 可回滚"；set_layout 重排全部节点后，用户下一次 Ctrl+Z 回滚的是更早的无关操作。
7. **展开预览的撤销无效**：render.js:1955 togglePreviewMorph 先翻转 it.previewOpen 再 pushHistory → 快照里已是翻转后状态，Ctrl+Z 看似无效果。
8. **退出确认无兜底**：main.js:121-126 close 一律 preventDefault 等渲染层弹 modal；渲染层卡死/白屏（onShowQuitModal 注册在 init 深处）→ 窗口永远关不掉只能任务管理器。且 isQuitting 仅由 confirm-quit 设置，其它 app.quit() 路径（如 macOS Cmd+Q，配置了 dmg）会被 abort。→ 加 2-3s 超时兜底 + before-quit 设 isQuitting。

## 四、P2 —— 体验/边界破坏（12 项）

1. **中文输入法回车冲突**：全代码无 isComposing/composition 处理；全局 keydown 在组合期间把 Enter 当提交+加同级（app.js:429-440）。Windows Electron 被 key==="Process" 巧妙躲过，网页版/macOS 上确认候选词会提前提交拼音并冒出兄弟节点；Escape 会取消整个编辑。一行修复：`if(e.isComposing)return;`。
2. **弹窗打开时快捷键穿透**：isTyping() 只查 INPUT/TEXTAREA；确认类弹窗（如退出确认）聚焦在按钮上 → Del 能删弹窗背后的选中元素、Tab/Enter/C/A/P/N/B 全部照常改画布、Esc 是清空选区而不是关弹窗。
3. **部分鼠标滚轮不能缩放**：interaction.js:90 `Math.abs(ay%100)>1` 把 120 增量/带横向漂移的鼠标滚轮判成触控板 → 只平移不缩放（Ctrl+滚轮仍可缩放；±100 整增量的鼠标正常）。
4. **鱼骨/时间轴只排两层**：layout.js:177-219 根+孙为止，三层以下原地不动，且 applyAutoLayout 不再跑全局避让 → 深树切换布局后新旧节点重叠。
5. **HUD 点击重置缩放错位一档**：app.js:245 取 rects[length-2]（zoom rect 是最后 push 的，应取 -1）→ 点最后一个计数段会意外重置缩放，点"缩放 NN%"反而无效；空画布时永远无效。
6. **导出 PNG 可能烙进选择框/HUD**：render.js:1007-1058 导出期间全局 ctx/W/H/camera 换到离屏画布，`await getWatermarkImg()`（每种水印+主题首次）让 rAF 渲染插进来画到导出图上。
7. **pv 窗口两套缩放控制器打架**：preview.js:160-170（头部 −/+/重置，闭包 pvZoom）与 :306-315（内容栏 −/输入框/+，读写 dataset.pvZoom）互不同步 → 混用会回跳、两处读数不一致。
8. **水印图路径指向已退役的 g11**：render.js:950 `g11/assets/watermarks/…`，打包版不带 g11 → 每次导出 404 静默回退文字水印（网页版靠仓库里残留的 g11 才正常）。
9. **笔画/连线完成不落盘**：interaction.js:429,433 只 render() 不 saveStateDebounced（其它分支都有）→ 30 秒自动保存窗口内崩溃丢最后一笔。
10. **storagePath 是死设置**：可设置、有成功 toast，但无任何消费者（导出走对话框、附件在 IndexedDB）→ "附件、导出文件、备份将存到此目录"是假的。
11. **"清除预览缓存"是 no-op**：删 `pv_*` localStorage 键，但没人写这些键；真缓存 previewCache Map（app.js:99）没动 → 成功 toast 是假的（且用原生 confirm，不合自定义弹窗惯例）。
12. **"删除展开"波及全部展开节点**：editors.js:93 无参调 collapseDetailInPlace() → 其它节点正开着的阅读面板一起被收起（G6 多实例下）。
