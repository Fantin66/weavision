# 织见 · 思维关系板 — 前端设计优化分析

> 基于对产品设计手册 v6.2 与 `织见-思维关系板.html`（CSS 284 行 + JS 4408 行）的完整代码审查

---

## 一、设计体系层面：颜色与主题

### 1.1 暗色模式实现方式脆弱

**现状**：暗色模式有两套并行但互不相通的机制：
- CSS 层：`[data-theme="dark"]` 选择器只覆盖了侧栏、便签编辑器、focusHud 等少量组件
- JS 层：`applyTheme()` 函数用 `root.style.setProperty()` 逐条覆写 CSS 变量

这导致暗色模式的变量切换完全依赖 JS 运行时，且 `[data-theme="dark"]` 的 CSS 规则与 JS 覆写的变量可能冲突或不一致。

**改法**：统一为纯 CSS 变量主题系统。在 `:root` 定义亮色变量，在 `[data-theme="dark"]` 选择器内统一覆写全部变量。`applyTheme()` 只负责切换 `data-theme` 属性，不再逐条 setProperty。这样：
- 主题切换更可靠（不依赖 JS 执行时序）
- 新组件只需引用 CSS 变量，自动适配双主题
- 便于后续扩展更多主题（如高对比度、护眼绿等）

### 1.2 画布绘制颜色硬编码散落

**现状**：Canvas 绘制中大量颜色值硬编码在绘制函数内，通过 `dc(light, dark)` 函数手动传参。例如：
- 聚焦高亮：`"rgba(10,132,255,.6)"` / `"rgba(52,199,89,.6)"`
- 节点选中：`"rgba(10,132,255,.8)"`
- 展开内容背景：`"rgba(10,132,255,.055)"` / `"rgba(10,132,255,.13)"`
- 搜索高亮：`"#ff9f0a"` / `"rgba(255,159,10,.55)"`

这些颜色无法通过改一处变量就全局生效，暗色适配全靠手动配对，极易遗漏。

**改法**：建立画布专用颜色常量表（JS 对象），与 CSS 变量一一映射：
```js
const C = {
  accent: { l: "#0a84ff", d: "#0a84ff" },
  focusRing: { l: "rgba(10,132,255,.6)", d: "rgba(10,132,255,.6)" },
  searchHi: { l: "#ff9f0a", d: "#ff9f0a" },
  // ...
};
// 使用时：c.strokeStyle = C.focusRing[state.dark?'d':'l'];
```
或更进一步，在 `render()` 开头读取 `getComputedStyle` 把 CSS 变量同步到 JS 常量，实现 DOM 与 Canvas 共用同一套色板。

### 1.3 品牌色彩缺乏辨识度

**现状**：主色 `#0a84ff` 是 Apple 系统蓝，便签 7 色、连线 7 色都是 iOS 系统色板。产品名叫"织见"，品牌字体用楷体，但配色完全没有呼应品牌气质。

**改法**：建议定义一组有"织"感的品牌色——偏靛蓝/藏青的深邃蓝（如 `#1a4d8f` 或 `#2c5282`）作为主色，搭配一组偏哑光的便签色（降低饱和度的莫兰迪色系），与楷体品牌字形成统一气质。关系类型的颜色也可从 iOS 系统色调整为更有语义的配色（反证用暖红、证据用紫罗兰等已有方向是对的，但色值可以更沉稳）。

## 二、字体与排版

### 2.1 节点字号不随缩放适配

**现状**：导图节点字号固定为 14/13/12.5px（按层级），在画布坐标系中是固定值。缩放到 30% 时文字仍然按原始尺寸渲染，导致大量文字堆叠不可读；放大到 200% 时文字又过大。

**改法**：引入缩放感知的字号策略：
- 当 `zoom < 0.5` 时，根节点和一级节点保持可读字号，二级以下节点改为只显示色块/短标签（省略文字）
- 当 `zoom > 1.5` 时，可以适当增大字号或显示更多展开内容预览
- 或者采用"文字密度"策略：根据视口内可见节点数量动态决定显示文字长度（少则全显示，多则截断）

### 2.2 品牌字体回退链不够稳健

**现状**：`--brand-font` 设为 `"STMaiti","KaiTi","Noto Serif SC","Source Han Serif SC","Songti SC","SimSun",serif`。在非 macOS/Windows 中文系统上，KaiTi 和 STKaiti 几乎不存在，会回退到宋体甚至默认 serif，品牌气质断裂。

**改法**：引入 Web Font 加载机制，至少为品牌名"织见"二字和标题级文字加载一套楷体 Web Font（如 Google Fonts 的 "LXGW WenKai" 或 "Ma Shan Zheng"），确保跨平台一致性。可以只加载标题用到的有限字重，控制体积。

### 2.3 展开内容的 Markdown 渲染过于轻量

**现状**：`drawDetail` 在 Canvas 上手绘 Markdown 行，只支持标题/列表/引用/行内代码/粗体斜体。不支持表格、图片、链接。手册自己在 9.1 差距分析第 7 条也提到了这一点。

**改法**：展开内容改用 DOM 层叠加渲染（而非 Canvas 手绘）。在元素展开时，于元素位置上方创建一个绝对定位的 `<div>`，用成熟的 Markdown 渲染库（marked.js / markdown-it）生成 HTML，支持表格、图片、链接等完整 Markdown 语法。这样既解决了 Canvas 文字渲染能力有限的问题，也让展开内容可选中、可复制、可点击链接。形变动画仍然可以驱动 DOM 层的位置和尺寸。

## 三、画布渲染性能

### 3.1 无视口裁剪，全量重绘

**现状**：`render()` 每帧遍历 `state.items` 全部元素绘制，`drawMindConnections` 和 `drawLinks` 也遍历全部连线和节点。手册已知问题 #8 提到"大画布仍需空间索引和按视口绘制"。

**改法**：
1. **视口裁剪**：在 `render()` 中计算当前可视区域（`camera.x` 到 `camera.x + W/zoom`），只绘制 bounds 与视口相交的元素
2. **空间索引**：维护一个简单的网格哈希（cell 大小 200×200），元素移动时更新所属网格；绘制时只遍历视口覆盖的网格
3. **分层 Canvas**：用一个 Canvas 专门画背景网格（只在 camera 变化时重绘），另一个 Canvas 画内容（每次状态变化时重绘），减少背景重绘开销

### 3.2 命中检测线性搜索

**现状**：`hitTest` 对所有元素做矩形碰撞检测，复杂度 O(n)。

**改法**：同样用空间索引，点击时只检测点击位置所在网格及相邻网格的元素。对于连线这种非矩形元素，可以先用包围盒粗筛，再对候选连线做点到曲线距离判断。

## 四、布局系统

### 4.1 自动排版对复杂树仍有遮挡

**现状**：`autoLayout` 的 `subtreeH` 只累加子节点高度，不计算子树宽度。当不同子树的子节点宽度差异大时，右侧子树可能向左侵入左侧子树的空间。手册已知问题 #1 承认"复杂树结构仍可能遮挡"。

**改法**：
- `subtreeH` 改为同时计算子树的包围盒（宽和高），布局时检测子树间是否有水平重叠，有则增加水平间距
- 或引入"轮廓"算法（轮廓合并）：计算每个子树的上下轮廓线，合并时检测轮廓冲突，自动增加间距。这是成熟的树布局算法（如 Reingold-Tilford 的改进版）

### 4.2 避让算法过于简单

**现状**：`smartPlace` 只向下推（`it.y = ob.y + ob.h + GAP`），`avoidOverlap` 只做简单推开，可能推到不合理位置。手册已知问题 #2/#3 承认这一点。

**改法**：
- `smartPlace` 改为螺旋搜索或射线搜索：从目标位置出发，沿 8 个方向试探，找最近的非重叠位置
- `avoidOverlap` 引入力导向微调：重叠元素互相施加排斥力，迭代几次后收敛到自然避让位置
- 明确三层逻辑的边界（手册 #3 已提出）：新增时自动排、拖动时局部避让、手动点按钮才全量重排

### 4.3 发散布局固定半径

**现状**：`radialLayout` 用固定 `radius = 220 + (depth-1)*185`，不根据节点大小和子树规模自适应。

**改法**：根据每个分支的子树规模动态分配扇区角度，根据节点宽度调整半径，避免不同分支互相侵入。

## 五、交互与可用性

### 5.1 小把手在低缩放下难以命中

**现状**：展开内容把手和折叠把手的命中区域用 `pad = 3/z` 扩展，在 zoom=0.3 时 pad≈10px，把手本身只有 `18/z ≈ 60px`，看似够大；但把手在画布坐标系中只有 18px 宽，在低缩放下视觉上很小，用户可能看不到也点不准。

**改法**：
- 把手视觉大小设最小值：`Math.max(18/z, 14)` px（屏幕空间），确保任何缩放下都至少 14px 可见
- 命中区域设最小值：`Math.max(box.w + pad*2, 24)` px（屏幕空间），确保至少 24×24px 可点
- 或将把手改为 DOM 层叠加（类似 selbar），在选中时显示在元素旁边，始终用屏幕坐标系定位

### 5.2 缺少键盘导航

**现状**：方向键没有绑定节点间导航。用户在画布上只能用鼠标点击切换选中，无法用键盘在节点间移动。

**改法**：
- 方向键 ← → ↑ ↓ 导航到相邻节点（按方向找最近的同级/父子节点）
- Tab 已用于加子节点，可以用 Shift+Tab 导航到子节点的第一个；用方向键做空间导航
- Enter 已用于加同级，可以用 Shift+Enter 或 Alt+方向键做纯导航

### 5.3 连接点发现性差

**现状**：节点右侧的蓝色连接点用 `rgba(10,132,255,.25)` 绘制，透明度极低，用户很难发现这是可拖拽的。只有手册和帮助里写了"节点蓝点拖出"。

**改法**：
- 选中节点时，连接点高亮放大（从 3.5px 变 5px，透明度从 .25 变 .8）
- hover 到节点右侧区域时，连接点弹出动画 + tooltip 提示"拖拽建立子节点"
- 或在选中浮动条（selbar）上增加一个"加子节点"按钮，作为蓝点拖拽的替代入口

### 5.4 关系类型仅靠颜色区分

**现状**：5 种语义关系（关联/支撑/导致/反证/证据）用 5 种颜色区分，但无形状/图案编码。色盲用户无法区分；缩放小时线段颜色也不易辨认。

**改法**：
- 给每种关系类型增加线型编码：关联=实线、支撑=双线、导致=粗实线+箭头、反证=虚线+箭头、证据=点划线
- 在连线中点的批注标签上显示关系类型文字（小字号），不只靠颜色

## 六、视觉细节打磨

### 6.1 父子连线过于淡

**现状**：`drawMindConnections` 用 `globalAlpha=.3` 绘制父子连线，在浅色背景上几乎看不见，用户可能误以为节点之间没有关系。

**改法**：提高到 `.4-.5`，或在选中节点时，该节点的父子连线高亮到 `.8`，其余保持 `.25` 做对比。

### 6.2 附件角标溢出节点边界

**现状**：附件角标位置在 `b.x+b.w-8, b.y-2`，即节点右上角偏外，圆心在节点边界外 2px。视觉上角标"挂"在节点外面，与节点分离感强。

**改法**：改为 `b.x+b.w-10, b.y+2`，让圆心在节点边界内侧，角标"嵌"在节点上角，视觉更整体。或改为 badge 样式（小圆角矩形而非圆形），紧贴节点右上角内侧。

### 6.3 便签顶部高光条不自然

**现状**：`drawNote` 在便签顶部画了一条 `rgba(255,255,255,.28)` 的高光条（6px 高），模拟便签纸的折角/光影效果。但这是矩形裁剪的平直高光，不像真实便签的微妙渐变。

**改法**：改为顶部 8px 的线性渐变（从 `rgba(255,255,255,.22)` 到 `transparent`），更自然地模拟光线从上方照射的效果。

### 6.4 材料卡片视觉不统一

**现状**：
- 图片卡片：整张填充 + 底部黑色文件名条
- 链接卡片：蓝色标题 + 灰色域名，垂直居中
- 其他文件卡片：深色文件名 + 灰色类型标签，垂直居中

三种卡片的视觉重心和排版方式不一致，拖入画布后混排时显得杂乱。

**改法**：统一卡片结构——所有卡片顶部留一个 28px 高的"头部区"（含文件图标 + 文件名），下方为预览区（图片显示缩略图，链接显示域名+favicon，其他显示类型标签和大小）。这样混排时视觉节奏一致。

### 6.5 毛玻璃效果过度使用，视觉单调

**现状**：全应用 21 处 `backdrop-filter: blur()` —— 顶栏、侧栏、菜单、选择条、右键菜单、帮助面板、状态栏、聚焦 HUD、预览窗口、加载层、筛选栏、拖放遮罩、搜索结果、toast、模态框、详情面板、便签格式条、便签预览，几乎每个浮层都是毛玻璃。

这导致三个问题：
1. **视觉同质化**：所有浮层看起来一样，缺乏层次区分。重要的模态框和次要的 toast 视觉权重相同。
2. **性能负担**：这是一个 Canvas 重度应用，21 个 backdrop-filter 叠加在画布之上，每次画布重绘都可能触发毛玻璃层的重新合成，低端设备会明显卡顿。
3. **审美过时**：满屏毛玻璃是 2020 年的设计趋势，2025 年的设计更倾向"克制的玻璃"——只在关键浮层（模态框、菜单）用，其余用实色或半透明。

**改法**：分级处理浮层材质：
- **模态框、右键菜单、下拉菜单**：保留毛玻璃（这些是临时弹出层，需要融入背景）
- **顶栏、侧栏**：改为实色或微透明（非 blur），它们是常驻 UI，不需要融入画布
- **状态栏、筛选栏、toast**：改为实色半透明（如 `rgba(255,255,255,.92)`），不用 blur
- **选择条、focusHud**：可以保留轻量 blur（`blur(8px)`），但要区别于菜单的 `blur(24px)`

这样形成"常驻 UI 实色 → 操作浮层轻玻璃 → 弹出层重玻璃"的三级层次。

### 6.6 画布元素缺乏质感和层次

**现状**：Canvas 上绘制的节点、便签、卡片都是扁平色块 + 单层投影。根节点虽然有"实心填充 + 强阴影"，但仍然是纯色填充，没有渐变、纹理或深度感。所有节点看起来像彩色纸片贴在白纸上。

**改法**：
- **根节点**：加入微妙的纵向渐变（如品牌色从 `#1a4d8f` 到 `#2c5f9e`），模拟微弧面的光线感；底部加 1px 内阴影线模拟厚度
- **一级节点**：白底加极淡的同色系渐变背景（如蓝色节点用 `linear-gradient(180deg, #f0f6ff, #e6f0ff)`），比纯白更有质感
- **便签**：加入纸质纹理感——用极细的噪点 pattern（或 CSS 的 `repeating-linear-gradient` 模拟纸纹），让便签真的像纸
- **材料卡片**：图片卡片加 1px 内边框（`inset 0 0 0 1px rgba(255,255,255,.15)`），让图片有"相框"感
- **投影体系统一**：当前投影参数散落各处（`shadowBlur` 从 5/z 到 14/z 不等），建议建立 3 级投影常量：`SHADOW_SM / SHADOW_MD / SHADOW_LG`，按元素层级使用

### 6.7 连线缺乏流动感与美感

**现状**：
- 父子连线：`globalAlpha=.3` 的纯色贝塞尔曲线，无箭头，无渐变，无动效
- 语义关系线：虚线贝塞尔 + 简单三角箭头 + 小圆点端点，`globalAlpha=.48`
- 自定义连线：纯色直线 + 三角箭头

所有连线都是静态的、功能性的，缺乏"织"的视觉隐喻。产品叫"织见"，连线是"织"的核心视觉载体，但目前连线看起来和普通流程图工具无异。

**改法**：
- **父子连线加渐变**：从父节点颜色渐变到子节点颜色（`createLinearGradient`），让连线有"传承"的视觉感，而不是单色
- **选中节点的父子线加流动光点**：在连线上画一个沿贝塞尔路径移动的小光点（用 `bezierPoint(t)` 计算位置），周期 2s 循环，暗示信息从父流向子（或反向）。只在选中节点的连线上激活，避免全屏光点噪音
- **语义关系线端点美化**：当前端点是 3.5px 实心圆点，改为带白色描边的小圆环（外环=关系色，内白），更精致
- **箭头优化**：当前箭头是简单三角，改为流线型箭头（尾部略凹），更有设计感
- **关系标签背景美化**：当前是白底圆角矩形，改为带关系色左边框的标签（类似 Notion 的 callout 样式），左侧 3px 竖条 = 关系色，背景 = 关系色的 8% 透明

### 6.8 缺少画布空状态的引导设计

**现状**：画布为空时只有空白网格，没有任何引导文字或视觉提示。新用户打开应用看到一张空白网格，不知道该做什么。材料库空状态有简单的 emoji + 文字（`#lib-empty`），但画布本身没有。

**改法**：画布为空时（`items.length === 0`），在画布中心绘制一个引导区：
- 品牌图标（大号，低透明度）+ "双击任意位置开始织网" 提示
- 下方三个快捷入口图标：新建节点、导入材料、从材料库拖入
- 用 `fadeSlideIn` 动画进入，有内容后自动消失
- 这比空白网格友好得多，降低首次使用门槛

### 6.9 图标系统不够精致统一

**现状**：27 个图标定义为内联 SVG 字符串（`ICON` 对象）。问题：
- 描边粗细不统一：大部分 `stroke-width="2"`，但 folder 是 `1.8`，plus/expand/collapse 是 `2.4`，close 是 `2.2`
- 图标尺寸不统一：大部分 `width="16" height="16"`，但 copy/trash/folder 是 `14`，plus 是 `14`，expand/collapse 是 `13`
- 都是单色线条图标，没有填充图标变体，选中态只能靠颜色区分，视觉层次不够
- 部分图标路径过于简单（如 connector 就是两个圆+一条线），辨识度低

**改法**：
- 统一描边宽度：全局设 `--icon-stroke: 1.8`，所有图标统一引用
- 统一图标尺寸：UI 按钮图标统一 16px，内联小图标统一 14px
- 为关键功能图标增加"填充态"变体：选中工具时图标从线条变填充（如 mind 图标选中后圆点变实心），视觉反馈更强
- 考虑引入图标字体或图标组件库（如 Lucide），保证一致性

### 6.10 动效体系不够丰富，缺少"织"的动感

**现状**：CSS 定义了 5 个关键帧动画（`fadeSlideIn` / `popIn` / `pulseGlow` / `editorRise` / `filterRise`），覆盖了元素弹入、浮层弹出、编辑器升起。但缺少：
- 连线绘制动画（新连线从 A 端"织"到 B 端的过程）
- 聚焦模式过渡（背景淡出 + 焦点放大的连续动画，目前是瞬切）
- 关系建立反馈（C 键连接后的视觉确认）
- 跃迁过渡（跳转画布时的过渡动画）

**改法**：
- **连线生长动画**：新建语义关系时，贝塞尔曲线从 A 端沿路径"生长"到 B 端，0.4s 完成（类似 `drawMindConnections` 已有的 grow 机制，但语义关系线目前没有）
- **聚焦过渡**：进入聚焦时，非关联元素 `opacity` 从 1 渐变到 0（0.3s），焦点元素 `scale` 从 1 渐变到 1.15（0.3s），camera 同步平移。目前非关联元素是直接不画，焦点是直接 scale，没有过渡帧
- **跃迁过渡**：J 键跳转时，当前画布淡出（0.2s 缩小+模糊），目标画布淡入（0.2s 放大+清晰），像空间穿梭
- **关系建立脉冲**：C 键连接成功后，两端点同时发出一圈扩散波纹（类似 `pulseGlow` 但只播一次），0.5s 消失

### 6.11 网格背景缺少氛围层次

**现状**：网格背景是纯功能性的——细线 + 粗线（每 5 格加粗），无渐变、无晕染、无氛围。纯白或纯色背景上只有规则的网格线，像方格本，缺少空间感和沉浸感。

**改法**：
- **加入径向晕影**：在画布中心区域加一层极淡的径向渐变（从中心 `rgba(brand, .02)` 到边缘 `transparent`），让画布有"中心明亮、边缘渐暗"的空间感
- **网格线渐变**：网格线不用固定透明度，而是根据距视口中心的距离渐变（中心 `rgba(0,0,0,.04)` → 边缘 `rgba(0,0,0,.02)`），让网格本身有呼吸感
- **暗色模式氛围**：暗色背景不要纯黑（`#1c1c1e`），改为带极淡蓝调的深色（如 `#1a1a2e`），配合径向晕影，让暗色模式有"深夜书房"的氛围
- **可选的装饰性背景**：增加 1-2 种氛围背景预设（如"星点"= 随机散布的微小光点；"水纹"= 极淡的波浪线），让用户可以选择更有沉浸感的画布

### 6.12 品牌视觉表达不足

**现状**：品牌"织见 · Weavision"只在顶栏左上角出现——32px 的 logo 图 + 楷体"织见" + 蓝色小字"WEAVISION"。除此之外，画布、侧栏、浮层中没有任何品牌元素的呼应。产品叫"织见"，但整个应用里看不到"织"的视觉语言——没有织物纹理、没有经纬线隐喻、没有编织感。

**改法**：
- **品牌纹样融入画布**：在画布背景或边角加入极淡的织物纹理图案（经纬交错线的抽象图案，透明度 < .02），作为品牌水印
- **连线视觉隐喻"织"**：语义关系线可以加入极细的"经纬编织"纹理——虚线 pattern 改为短-长-短交替（像织物纹路），而非等距虚线
- **加载/空状态用品牌纹样**：画布空状态或加载态，用品牌图标的大号低透明度版本做背景装饰
- **侧栏底部品牌签**：侧栏底部加一个小的品牌标识区（logo 小号 + 版本号 + 一句话 slogan），增加品牌存在感
- **关于面板**：增加一个"关于织见"的模态框，讲述产品理念（树与网的第一性原理），用排版精美的图文呈现，让用户理解"为什么叫织见"

### 6.13 间距与比例缺乏节奏感

**现状**：大部分间距用固定值（`gap:4px`、`padding:0 12px`、`gap:10px`），没有基于比例的间距系统。元素间疏密不均——顶栏按钮间距 4px 很紧凑，侧栏列表间距 2px 更紧，但浮层内间距 6-10px 又较松。整体缺乏统一的间距节奏。

**改法**：建立基于 `4px` 基准的间距阶梯：
- `--sp-1: 4px`（按钮内间距、紧密排列）
- `--sp-2: 8px`（卡片内边距、常规间距）
- `--sp-3: 12px`（区块间距）
- `--sp-4: 16px`（分区间距）
- `--sp-5: 24px`（大区块间距）

全局替换散落的 `padding`/`gap`/`margin` 值为间距变量，形成"4-8-12-16-24"的节奏感。视觉上会更整齐、更有韵律。

### 6.14 圆角系统不统一

**现状**：圆角值散落且不统一——按钮 `9px`、菜单 `14px`、模态框 `18px`、预览窗口 `12px`、便签 `6px`、根节点 `14px`、一级节点 `11px`、二级节点 `9px`、三级节点 `8px`。没有规律可循。

**改法**：建立圆角阶梯：
- `--radius-sm: 6px`（便签、小标签）
- `--radius-md: 10px`（按钮、卡片、节点）
- `--radius-lg: 14px`（菜单、浮层）
- `--radius-xl: 18px`（模态框）
- `--radius-full: 999px`（筛选栏等胶囊形）

按元素类型映射到圆角变量，形成"小元素 6px → 中元素 10px → 浮层 14px → 模态框 18px"的层次。

## 七、界面 UI 组件设计

### 7.1 顶栏信息密度过高，缺少分区逻辑

**现状**：顶栏在 52px 高度内塞了：品牌区、撤销/重做、4 个菜单标签（布局/添加/关联/查看）、spacer、缩放组（缩小+百分比+放大+适应全部）、背景纹理、背景底色、明暗主题、帮助、导出、导入、搜索框——总共 15+ 个交互元素横排在一行。在 1366px 窄屏上已经拥挤，更窄的屏幕会更挤。

**问题**：
- 缩放组 5 个按钮连续排列，无视觉分隔，扫视时难以快速定位
- "布局/添加/关联/查看"四个菜单标签与右侧工具区之间缺少明确的分区线
- 导出/导入按钮用 `chip` 背景，与工具按钮视觉权重相同，但实际它们是数据操作，不是视图操作
- 搜索框被挤到最右侧，缩放区和搜索之间没有过渡

**改法**：
- **明确分区**：用 1px 竖分隔线将顶栏分为 4 个功能区——品牌区 | 编辑区（撤销重做 + 菜单标签）| 视图区（缩放 + 背景 + 主题）| 数据区（导入导出 + 搜索）。每区间加 `var(--card-border)` 竖线 + 8px gap
- **缩放组精简**：将"缩小+百分比+放大"合并为一个可点击的百分比显示（点击弹出滑块），释放 2 个按钮的空间
- **搜索框前置**：将搜索框移到菜单标签后面（编辑区内），因为搜索是高频操作，不应被挤到最右
- **导出/导入收进菜单**：将导出/导入从顶栏移到"查看"菜单的下拉中（或单独的"文件"菜单），顶栏只保留核心操作

### 7.2 侧栏三区比例失调

**现状**：侧栏 270px 宽，内部垂直排列三个区域：项目列表（max-h 140px）→ 画布列表（max-h 160px）→ 材料资源库（flex:1 占满剩余空间）。项目列表和画布列表高度被限制，材料库占大部分空间。

**问题**：
- 用户通常在 1-3 个项目间切换，140px 的项目列表区大部分时候是空的或只有 1-2 项，浪费空间
- 画布列表 160px 同理，小项目时只有 1 张画布
- 但材料库内容多时被挤到很小，需要频繁滚动
- 三区之间只有 1px 分隔线，视觉上不像三个独立区域

**改法**：
- **自适应高度**：项目区和画布区用 `max-height` + `flex-shrink:0`，但实际高度由内容撑开（不设固定 max-h），最少 1 项时只占 1 行高度。材料库区 `flex:1` 占剩余空间
- **可折叠分区**：每个区标题栏可点击折叠整个区（类似 VS Code 侧栏），折叠后只显示标题栏一行。用户可以折叠不常用的区
- **区标题视觉强化**：当前标题是 11px 大写灰色文字，存在感弱。改为加区图标（项目用 folder 图标，画布用 layout 图标，材料用 archive 图标），标题旁显示数量徽章
- **拖拽重排**：允许用户拖拽调整三个区的顺序（画布在上还是材料在上）

### 7.3 选择浮动条（selbar）功能不完整

**现状**：选中元素后显示的浮动条包含——类型标签、色板（便签/节点有）、预览按钮（卡片有）、加子节点+折叠（节点有）、复制、删除。但缺少几个高频操作：
- 没有"聚焦"按钮（F 键的核心功能，但浮动条上没有）
- 没有"连接选中"按钮（C 键功能，多选时需要）
- 没有"批注"按钮（A 键功能）
- 没有"展开内容"按钮（E 键功能）
- 没有"跃迁"按钮（J 键功能）

这些功能都在右键菜单里，但浮动条是更直觉的操作入口——用户选中元素后，眼睛会看向浮动条。

**改法**：浮动条分三段：
- 左段：类型标签 + 色板
- 中段：上下文操作按钮（节点=加子/折叠/聚焦；卡片=预览；通用=批注/展开内容）
- 右段：连接选中（多选时显示）/ 跃迁 / 复制 / 删除

用 `ssep` 分隔线区分三段。按钮太多时可以只显示图标，hover 时 tooltip。

### 7.4 右键菜单结构不够清晰

**现状**：右键菜单用 `csep` 分隔线分了 4-5 段，但分隔逻辑不够清晰——核心操作（聚焦/展开/批注/跃迁/连接）是一段，然后结构操作（加子/同级/折叠）是一段，然后颜色选择，然后复制/删除。颜色选择直接插在结构操作和复制之间，打断了操作流。

**改法**：
- **重组为 3 段**：核心钻探（聚焦/展开内容/批注/跃迁）→ 结构操作（加子/同级/折叠/连接）→ 颜色 + 复制/删除
- **颜色选择改为子菜单**：不用直接铺色板，改为"颜色 ▸"子菜单项，hover 展开色板，减少菜单高度
- **快捷键提示对齐**：当前 `mi-key` 右对齐但宽度不固定，改为固定宽度右对齐，所有快捷键对齐成一列
- **分组标题**：在每段分隔线上方加小字分组标题（如"钻探""结构""操作"），用 `section title` 样式

### 7.5 状态栏信息不够有用

**现状**：状态栏左下角显示——工具/筛选/元素数/缩放/坐标。信息是只读的（`pointer-events:none`），无法交互。

**问题**：
- 坐标信息对普通用户没有意义（显示的是画布世界坐标 x,y），不如显示"第几象限"或"距中心多远"
- 元素数只显示总数，不分类（不知道有多少节点/便签/材料）
- 缩放百分比不可点击（不能点击重置到 100%）
- 没有显示当前选中元素的信息

**改法**：
- **缩放可交互**：点击缩放百分比弹出缩放滑块，或点击重置到 100%
- **元素数分类**：显示"节点 N · 便签 N · 材料 N · 连线 N"，用小色点区分类型
- **选中信息**：选中元素时，状态栏增加一行显示选中元素的类型和名称
- **坐标改为相对**：显示距画布中心的相对位置，或显示当前视口覆盖的网格范围

### 7.6 模态框设计过于简单

**现状**：模态框只有 `modal-title` + `modal-body` + `modal-actions` 三段式结构，样式是毛玻璃圆角矩形。`showOptions` 生成的选项列表用 `opt-item` 卡片样式，`showPrompt` 生成单行输入框，`showLinkPrompt` 生成双行输入框。

**问题**：
- 所有模态框共用一套样式，但用途不同（确认操作 vs 输入文本 vs 选择选项）应该有不同视觉侧重
- 选项卡片 `opt-item` 视觉不错，但缺少 hover 态的明确反馈（只有 border 变色）
- 输入框 `modal-input` 只有一个 focus 态，没有输入验证反馈（如 URL 格式错误）
- 模态框没有关闭按钮（×），只能点遮罩或按 Esc 关闭

**改法**：
- **增加关闭按钮**：模态框右上角加 × 关闭按钮
- **选项卡片 hover 强化**：hover 时不仅 border 变色，还加微妙的背景色 + 轻微上移（`translateY(-1px)`）
- **输入验证**：`showLinkPrompt` 的 URL 输入框加实时验证——输入合法 URL 时边框变绿，非法时变红 + 下方提示
- **模态框尺寸自适应**：当前 `min-width:360px max-width:480px`，选项多的场景（如跃迁选择）内容被挤窄。改为根据内容自适应宽度，最大 560px

## 八、设计理念与视觉语言

### 8.1 整体设计语言缺乏自己的"性格"

**现状**：织见的视觉语言是"Apple 系统风格的中文效率工具"——毛玻璃、系统蓝、圆角矩形、SF 风格图标、macOS 风格窗口控制。这些元素拼在一起，让织见看起来像"又一个 macOS 原生应用"，而不是一个有独特品牌个性的产品。

**核心问题**：产品名叫"织见"，核心理念是"用连接织出全局"，但视觉上没有任何"织"的痕迹。整体设计语言是借来的（Apple 的），不是自己的。

**改法**：确立"织"的设计语言方向，不必完全抛弃现有 Apple 风格基础，而是在其上叠加品牌个性层：

1. **"织物"作为核心视觉隐喻**：不只在连线（6.7/6.12 已述），而是贯穿全局——
   - 画布背景的网格本身就是"经纬"，可以强化这一点：网格线不是死板的直线，而是有极微妙的"交织"效果（细线 + 粗线交叉处加 1px 亮点）
   - 节点之间的留白空间不是"空"，而是"未织的经纬"——空状态时可以用淡淡的织物纹理暗示"这里可以织"
   - 连接建立时的动画用"织"的动效——线从一端"拉"到另一端，像织布梭子穿过经线

2. **"见"作为视觉聚焦的语言**：聚焦模式不只是放大+高亮，而应该有"镜头对焦"的视觉语言——
   - 进入聚焦时，非焦点元素加轻微 blur（不只是淡出），模拟"焦外"
   - 焦点元素加极淡的"对焦框"（四角 L 形标记，像相机取景器），而非简单的蓝色描边
   - 聚焦 HUD 用"取景器"的视觉语言——角标 + 十字线，而非普通 pill 形

3. **确立品牌色板**：从 Apple 系统蓝（#0a84ff）转向更有"织"感的色彩——靛蓝/藏青系。靛蓝（indigo）本身就和"织染"文化相关，是"织"的天然色彩语言。主色建议 `#3b5998` 或 `#2c5282` 方向的沉稳靛蓝。

### 8.2 扁平化是否过度

**现状**：全应用是纯扁平设计——色块、描边、无渐变、无阴影层次（除节点和便签的单层投影）。这符合 2015-2020 年的扁平化趋势，但 2025 年的设计已经在回归"适度深度"（Apple 自身也在 VisionOS 中引入了更多层次和深度）。

**问题**：对于"思维关系板"这种需要空间感的应用，纯扁平化让元素缺乏"在空间中的位置感"——所有元素看起来在同一平面上，无法通过视觉深度感知层次关系。

**改法**：引入"适度深度"（不是拟物，是空间层次）：
- **Z 轴层次**：根节点投影最大（`shadow-lg`），一级节点中等（`shadow-md`），二级以下最小（`shadow-sm`），通过投影大小暗示层级深度
- **聚焦模式的深度分离**：非焦点元素加 `transform: scale(.95)` + blur，模拟"后退"；焦点元素保持原大小，形成"前进"的对比
- **展开内容的层叠感**：展开内容区域加比节点本身更深的投影，让它看起来"浮"在节点之上（而不是在节点内部生长），同时保持位置连接
- **微妙的渐变回归**：根节点和品牌元素可以用极淡的纵向渐变（顶亮底暗，2-3% 差异），模拟微弧面光线

### 8.3 毛玻璃作为设计语言的定位

（6.5 已述毛玻璃过度使用的问题，这里补充设计理念层面的思考）

**现状与定位反思**：毛玻璃（backdrop-filter）在 2020 年是"高级感"的代名词，但 2025 年它已经是"默认审美"——每个应用都在用，反而失去了辨识度。

**设计理念建议**：毛玻璃应该从"默认材质"降级为"情境材质"——只在需要融入画布背景的场景用（如悬浮在画布上的操作浮层），其他场景用实色或有质感的半透明。更进一步，可以探索一种"织物纹理半透明"——浮层背景不是纯色半透明 + blur，而是带极淡织物纹理的半透明层，这样毛玻璃就变成了"织纱"，与品牌形成呼应。

## 九、字体与排版

### 9.1 字号系统缺乏层级规则

**现状**：应用中用到的字号有：8px（品牌英文）、10px（快捷键/批注/角标）、10.5px（计数/子标题）、11px（区标题/状态栏）、11.5px（文件大小/选项标签）、12px（菜单/按钮/列表项）、12.5px（菜单项/卡片文字/右键菜单）、13px（便签编辑器/展开内容）、14px（根节点文字）、17px（品牌名）。共 11 种字号，没有统一的层级规则。

**问题**：字号梯度太密（10/10.5/11/11.5/12/12.5 相差只有 0.5px），肉眼几乎无法区分，但增加了维护复杂度。

**改法**：建立 5 级字号阶梯：
- `--text-xs: 10px`（角标、快捷键提示、元信息）
- `--text-sm: 12px`（列表项、按钮、菜单项）
- `--text-base: 13px`（便签正文、展开内容）
- `--text-lg: 15px`（节点标题、模态框标题）
- `--text-xl: 17px`（品牌名、大标题）

全局替换所有 font-size 为这 5 个变量，消除 10.5/11.5/12.5 等中间值。

### 9.2 字重使用不够语义化

**现状**：字重从 500 到 800 都有——500（tbtn）、600（列表项/卡片文字）、700（菜单标签/品牌名/根节点）、800（品牌英文）。但同一语义层级的文字用了不同字重——比如侧栏标题用 700，列表项也用 600，根节点用 700 但一级节点也用 600，层级区分不明显。

**改法**：建立 3 级字重语义：
- `--weight-normal: 400`（正文、说明文字）
- `--weight-medium: 600`（列表项、按钮、次级标题）
- `--weight-bold: 700`（区标题、根节点、品牌名、主操作按钮）

暗色模式下可以全局加 100（400→500, 600→700），因为浅色背景下细字更清晰，暗色下需要加粗补偿。

### 9.3 中文字体选择缺乏策略

**现状**：三套字体预设——"界面雅黑"（微软雅黑系）、"书卷宋体"（思源宋体系）、"手写楷体"（霞鹜文楷系）。界面默认用雅黑，品牌名用楷体。展开内容和便签的 Markdown 预览也用雅黑。

**问题**：
- 雅黑是"安全但不出彩"的选择，每个中文应用都在用，缺乏辨识度
- 品牌名用楷体，但正文/节点全用雅黑，品牌气质没有渗透到内容层
- 宋体预设存在但默认不用，用户如果不主动切换就感受不到"书卷感"
- 楷体在非 macOS/Windows 上可能不存在（2.2 已述）

**改法**：
- **品牌渗透到内容**：至少根节点和一级节点的文字用品牌字体（楷体或宋体），让"织见"的气质不只停留在 logo 上，而是渗透到画布内容中。这与 8.1 的"确立品牌性格"一脉相承
- **智能字体分配**：根据内容类型自动选字体——标题用楷体（手写感），正文用宋体（阅读感），便签用雅黑（效率感），元信息用等宽字体
- **Web Font 加载**：为品牌字体加载 Web Font（至少加载"霞鹜文楷"的常用字），确保跨平台一致
- **等宽字体引入**：批注、快捷键提示、代码块等需要等宽对齐的地方，统一用一套等宽字体（当前只在 `mi-key` 用了 `monospace`，但没指定具体字体）

### 9.4 行高和字间距缺乏统一

**现状**：行高散落各处——便签 `line-height:19px`（固定值），节点文字用 `text-baseline:middle`（无行高），展开内容 `line-height:1.6`（比例值），预览面板 `line-height:1.7`（比例值），状态栏无行高设置。字间距只有品牌名用了 `letter-spacing:.1em`，其余无设置。

**改法**：
- **行高系统**：建立 3 级行高——`--lh-tight: 1.2`（标题、按钮）、`--lh-normal: 1.5`（正文、列表）、`--lh-relaxed: 1.7`（阅读、预览）
- **字间距规则**：大标题用 `letter-spacing: .02em`（微开），全大写文字（区标题、品牌英文）用 `.08-.1em`，正文不设字间距（中文默认已合适）

## 十、动画与过渡

### 10.1 缓动曲线不统一

**现状**：CSS 中用了多种缓动曲线——`cubic-bezier(.2,.8,.2,1)`、`cubic-bezier(.4,0,.2,1)`、`cubic-bezier(.34,1.56,.64,1)`、`ease`、`cubic-bezier(.6,.15,.4,.85)`。同一个 hover 效果，有的用 `.18s ease`，有的用 `.18s cubic-bezier(.4,0,.2,1)`，有的用 `.15s cubic-bezier(.34,1.56,.64,1)`。

**问题**：缓动曲线不统一导致动画"手感"不一致——有的弹、有的滑、有的顿，用户感知不到统一的运动语言。

**改法**：定义 3 套缓动曲线常量：
- `--ease-out: cubic-bezier(.2,.8,.2,1)`（默认出场：快进慢出，用于 hover、展开）
- `--ease-spring: cubic-bezier(.34,1.56,.64,1)`（弹性出场：用于弹出、选中，有微弹感）
- `--ease-snap: cubic-bezier(.4,0,.2,1)`（快速切换：用于位移、缩放，无弹）

全局替换所有 transition 的缓动曲线为这 3 个变量，按场景选用。

### 10.2 动画时长缺乏节奏

**现状**：动画时长有 `.1s`、`.12s`、`.15s`、`.16s`、`.18s`、`.2s`、`.22s`、`.24s`、`.25s`、`.3s`、`.5s` —— 11 种时长，从 100ms 到 500ms 跨度很大，但选择没有规律。

**改法**：建立 4 档动画时长：
- `--dur-instant: 100ms`（微反馈：hover 变色、按下反馈）
- `--dur-fast: 180ms`（快速过渡：面板展开、按钮位移）
- `--dur-normal: 280ms`（标准过渡：浮层弹出、面板滑动）
- `--dur-slow: 450ms`（长动画：进场、视角动画、形变展开）

### 10.3 Canvas 动画与 CSS 动画脱节

**现状**：CSS 动画用于 DOM 层（浮层弹出、按钮 hover），Canvas 动画用于画布元素（节点弹入 `birth`、连线生长 `grow`、形变展开 `animateDetailGeometry`）。两套动画各自运行，时间曲线和时长不一致——CSS 弹出用 `.18s spring`，Canvas 节点弹入用 `380ms` 三次方缓动，形变展开用 `230ms` 四次方缓出。

**改法**：统一动画参数到 JS 常量，与 CSS 变量对应：
```js
const ANIM = {
  instant: 100, fast: 180, normal: 280, slow: 450,
  easeOut: t => 1-Math.pow(1-t,3),      // 对应 CSS --ease-out
  easeSpring: t => ...,                   // 对应 CSS --ease-spring
  easeSnap: t => 1-Math.pow(1-t,4),     // 对应 CSS --ease-snap
};
```
Canvas 动画的 `duration` 和 `ease` 函数统一从 `ANIM` 取值，确保 DOM 和 Canvas 的动画手感一致。

### 10.4 缺少悬停（hover）的渐进式反馈

**现状**：Canvas 上元素的 hover 效果只有一种——画一个虚线/实线边框（`render()` 中的 hover 分支）。没有渐进式反馈——鼠标接近时无预览，hover 上时只有一个边框。

**改法**：
- **hover 预发光**：鼠标 hover 到节点时，先加极淡的背景光晕（`shadowColor` + `shadowBlur`），延迟 100ms 后再画边框，形成"注意到 → 关注"的两段式反馈
- **hover 展开预览**：hover 到含 `detail` 的节点时，在节点旁显示一个小的"文档"图标提示（而非要等到选中才看到把手），暗示"这里有内容可展开"
- **hover 连接点放大**：hover 到节点右侧蓝点区域时，蓝点放大 + 颜色变亮 + 显示"拖出建立子节点"tooltip

### 10.5 聚焦模式缺少过渡帧

（6.10 已提及，这里补充实现层面的设计）

**现状**：进入聚焦时，`enterFocus` 直接修改 `state.focusMode` 然后 `render()`，非关联元素直接不画，焦点元素直接 scale 1.15。`animateCamera` 只负责 camera 平滑移动，不负责元素的显示/隐藏过渡。

**改法设计**：引入"聚焦过渡帧"机制：
1. 进入聚焦时，先记录所有元素的当前 alpha（1.0）和 scale（1.0）
2. 在 280ms 内，非关联元素 alpha 从 1→0（渐隐），关联元素 alpha 保持 1 但加高亮边框渐入，焦点元素 scale 从 1→1.15
3. 过渡期间每帧 render，根据进度参数控制每个元素的 alpha 和 scale
4. 过渡完成后，非关联元素才完全不画（节省性能），焦点保持放大态
5. 退出时反向：非关联 alpha 0→1，焦点 scale 1.15→1，280ms 后恢复

## 十一、交互细节

### 11.1 拖拽体验缺少视觉引导

**现状**：拖拽元素时，元素跟随鼠标移动，但没有以下引导：
- 拖拽时无"幽灵"预览（元素本体直接跟鼠标走，看不出"正在拖拽"还是"正在移动"）
- 拖拽便签/材料到节点上时，关联挂接的高亮提示（⊕）只在代码逻辑里有，视觉反馈不够明显
- 拖拽节点蓝点时，无连线预览（不知道拖到哪里会建立什么关系）

**改法**：
- **拖拽幽灵**：拖拽时元素本体半透明（`globalAlpha=.6`），在鼠标位置画一个实色"幽灵"投影，暗示"正在搬运"
- **挂接目标高亮**：拖拽便签/材料时，画布上所有节点轻微高亮（边框变亮），hover 到的节点强烈高亮（放大 + 发光 + ⊕ 图标弹出），明确告诉用户"可以挂到这里"
- **蓝点拖拽预览线**：从节点蓝点拖出时，实时画一条从蓝点到鼠标位置的贝塞尔曲线（半透明蓝色），鼠标 hover 到目标节点时曲线变实色 + 目标节点高亮，明确暗示"松开会建立父子关系"

### 11.2 多选缺少视觉区分

**现状**：Ctrl+点击多选时，第一个选中元素和后续选中元素的视觉表现相同（都画蓝色选中框）。手册说"第一个为连接父项"，但视觉上看不出谁是父项。

**改法**：
- **主选中态**：第一个选中元素（连接父项）用实线蓝色边框 + 填充淡蓝背景
- **次选中态**：后续选中元素用虚线灰色边框，无背景填充
- **连接预览**：多选 2+ 个元素时，在主选中和每个次选中之间画一条半透明虚线预览连接，暗示"按 C 会连接这些"

### 11.3 搜索结果交互不够流畅

**现状**：搜索输入后，结果列表显示在搜索框下方。回车跳转到下一个结果，画布平移到目标。但：
- 搜索结果列表没有键盘上下箭头导航（只能鼠标点击或回车循环）
- 跳转后高亮是临时的（橙色虚线框），几秒后消失，用户如果离开再回来找不到
- 搜索无结果时只显示"无结果"，没有建议（如模糊匹配、搜索展开内容）

**改法**：
- **键盘导航**：↑↓ 在搜索结果间移动，Enter 跳转，Esc 清除搜索
- **持久高亮**：搜索结果高亮保持到搜索关闭，不自动消失
- **无结果优化**：显示"未找到「query」" + 建议"试试搜索展开内容"（如果当前只搜了标题）

### 11.4 拖放导入的反馈不够丰富

**现状**：从外部拖放文件到画布时，显示一个蓝色虚线边框的遮罩 + "松开以添加到画布"文字。但遮罩是全屏的，不区分拖到画布还是拖到侧栏。

**改法**：
- **分区高亮**：拖放时，画布区和侧栏材料库区分别高亮——拖到画布=添加为材料卡片，拖到侧栏=导入到材料库。hover 到哪个区，哪个区高亮
- **预览缩略图**：拖放图片时，在遮罩内显示图片缩略图预览
- **多文件计数**：拖放多个文件时，遮罩显示"松开添加 N 个文件"

### 11.5 缺少撤销/重做的视觉反馈

**现状**：Ctrl+Z / Ctrl+Shift+Z 撤销重做时，画布直接变化，没有额外的视觉反馈。用户不知道"刚才撤销了什么操作"。

**改法**：
- **撤销 toast**：每次撤销/重做时，toast 显示操作描述（如"撤销：添加节点""重做：建立连接"），让用户知道做了什么
- **元素回溯动画**：撤销添加元素时，元素用"弹入"的逆动画消失（缩小+淡出）；撤销移动时，元素从新位置滑回旧位置

### 11.6 缺少加载和等待状态

**现状**：应用是纯本地的，大部分操作即时完成。但有几个场景需要等待——CDN 加载预览组件（PDF.js / docx-preview / xlsx）、大文件导入、AI 编排执行。当前这些场景只有 `spinner` 旋转动画，没有进度提示。

**改法**：
- **CDN 加载提示**：首次打开 PDF/Word 预览时，显示"正在加载预览组件…" + 进度条（而非只有 spinner）
- **大文件导入**：导入大文件时显示进度条 + 文件名
- **AI 执行**：AI 编排画布时显示分步进度（"读取快照 → 生成计划 → 创建节点 → 建立关系"）

## 十二、图标系统

### 12.1 图标缺少视觉层级

（6.9 已述图标统一性问题，这里补充层级和语义）

**现状**：所有图标都是单色线条图标，用 `currentColor` 继承父元素颜色。选中态只靠背景色区分，图标本身不变。

**改法**：建立图标的"线/填"双态系统：
- **默认态**：线条图标（stroke only），轻量
- **激活态**：填充图标（fill + stroke），加重
- 例：`mind` 图标默认是空心圆点连线，激活后圆点变实心、连线变粗
- 例：`focus` 图标默认中心圆是空心，聚焦激活后中心圆变实心
- 这比纯靠背景色区分更直觉——用户看到"图标变实了"就知道"功能激活了"

### 12.2 文件类型图标缺乏辨识度

**现状**：9 种文件类型图标（img/pdf/doc/sheet/slide/text/link/media/other）都是 24×24 线条 SVG，用不同颜色区分（橙/红/蓝/绿/橙/灰/灰/紫/灰）。但：
- pdf 和 doc 图标都是"文件+折角"形状，只靠颜色区分，色弱用户难辨
- text 和 other 也都是"文件+折角"形状
- slide 和 img 都用了矩形，辨识度低

**改法**：
- **形状差异化**：每种文件类型用独特的形状隐喻——图片= mountains in frame、PDF= "PDF"字样标签、Word= "W"字样或横线文档、表格= 网格、演示= 幻灯片屏幕、文本= 引号或 T 字标、链接= 链条、音视频= 播放三角、其他= 通用文件
- **颜色+形状双编码**：不只靠颜色，还靠形状区分，色盲用户也能辨识
- **文件图标用填充而非线条**：文件类型图标用"填充色块 + 白色线条"（类似 macOS Finder 的文件图标），比纯线条更醒目，在侧栏小尺寸下更易辨认

### 12.3 图标缺少尺寸响应式

**现状**：图标用固定 `width="16" height="16"` 等属性写死在 SVG 字符串里。在侧栏（窄列）和顶栏（宽行）用同样大小的图标，侧栏显得拥挤。

**改法**：图标尺寸用 CSS 控制（`width/height` 用 `em` 或 CSS 变量），而非写死在 SVG 属性中。定义 `--icon-sm: 14px` 和 `--icon-md: 16px`，侧栏用 sm，顶栏用 md。

## 附录：代码架构（影响前端可维护性）

### A.1 单文件 4400 行，无模块化

**现状**：全部 JS 在一个 `<script>` 标签内，渲染、交互、数据管理、布局、预览、AI 接口全部混在一起。

**改法**：按职责拆分为模块（不一定要上构建工具，可以用 ES Module + `<script type="module">`）：
- `render.js`：render + draw* 系列
- `layout.js`：autoLayout + radial + bothSides + avoid 系列
- `interaction.js`：事件绑定 + hitTest
- `state.js`：状态管理 + 撤销重做
- `preview.js`：预览窗口
- `ai.js`：AI 编排接口

### A.2 状态直接突变，无防护

**现状**：`state` 是全局对象，各处直接 `state.items.push()`、`state.camera.x = ...` 突变，撤销重做靠 `pushHistory()` 手动调用，极易遗漏。

**改法**：引入简单的状态管理中间层——所有突变走统一的 `commit(action, payload)` 入口，自动记录历史。或至少用 Proxy 拦截突变，自动触发 render。
